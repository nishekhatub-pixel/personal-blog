# R7 Digital Garden V2 现状设计审计

审计日期：2026-07-27  
模式：Redesign - Preserve，保留式增量升级

## 当前基础

项目已经具备完整 V1 公开站点、管理员认证、文章与项目 CRUD、评论审核、媒体上传、SQLite 与 MySQL 双 schema、SEO、RSS、Sitemap、Vitest 和 Playwright。工作树没有提交历史，所有现有文件仍未跟踪，因此任何修改都必须避免覆盖和批量替换。

## 当前品牌令牌

现有 `src/app/globals.css` 使用语义变量：

- 页面：`--canvas`
- 表面：`--surface`、`--surface-strong`
- 文字：`--ink`、`--muted`、`--quiet`
- 结构：`--line`、`--line-strong`
- 强调：`--accent`、`--accent-soft`、`--accent-ink`
- 状态：`--success`、`--danger`
- 阴影：`--shadow`

当前视觉是暖纸张底色、近黑文字与高亮绿色强调。暗色主题是暖黑绿表面。V2 不改变语义变量策略，但会把主强调色校准为克制琥珀橙，将绿色退回真实成功状态，并补充抬起、按下、花瓣和音乐环境光令牌。

字体使用中文系统无衬线栈和等宽技术字体，避免远程字体请求。该选择适合中文性能与可读性，应继续保留。展示标题通过字重、字距和尺寸形成层级，不混入无理由的装饰衬线体。

## 当前首页内容块

1. 大型品牌欢迎区。
2. 个人介绍。
3. 精选文章。
4. 精选项目。
5. 当前学习栈。
6. 成长时间线。
7. 音乐和运动兴趣。
8. 订阅区。

内容真实、文案语气适合学生身份，但首页接近长篇作品集。V2 要把它重组为长期居住的三栏个人空间，保留核心文案和有效内容，减少整屏展示段落，把文章、项目、说说、相册和音乐状态整合成首批 6 至 10 条内容。

## 当前布局与交互

- 最大内容宽度约 1400px。
- 首页主要使用 12 列网格与不对称图文布局。
- 卡片和媒体圆角为 8px 至 12px，按钮为胶囊。
- Motion Reveal 是独立 Client Component。
- 导航为 sticky，不遮挡 Footer。
- 移动端使用菜单，没有公共底部 Dock。
- 全局 reduced-motion 会关闭或压缩动画。
- 焦点环、跳转主内容、表单标签和最小触控尺寸已经建立。

V2 必须保留这些可访问性收益。新增 Motion 只放在交互叶子组件，不使用滚动事件监听，不动画布局尺寸。

## 当前数据与安全

- Prisma SQLite 与 MySQL schema 业务一致。
- `SiteSetting` 已经是键值配置，适合继续扩展。
- 图片上传验证声明 MIME、扩展名和文件签名，再经 Sharp 旋转、限制像素并重编码 WebP。
- 文件名使用 UUID，输出路径经过根目录边界校验。
- 管理操作验证管理员身份。
- 公开写入使用 Origin 校验、Zod、IP HMAC、蜜罐和频率限制。
- 外部 URL 当前仅允许 HTTPS，开发环境允许 HTTP。

V2 音频上传应独立实现，不把音频交给 Sharp。照片继续复用 Media。留言、友链申请、说说点赞和评论沿用相同的来源校验、哈希与限频原则。

## 当前 SEO 基线

- 根布局设置标题模板、描述、关键词、作者、Open Graph、Twitter Card 与 robots。
- 公开内容页使用真实 slug。
- RSS、Sitemap、robots 与 Open Graph 图片已经存在。
- `/blog` 与 `/projects` 使用路由组解决加载边界导致的 404 状态问题。
- 根级 loading 已移除，以确保不存在页面保持真实 404。

V2 不更改现有 slug、RSS 地址、Sitemap 行为和 404 边界。新增页面补充独立 metadata 和 Sitemap 条目。

## 应保留

- R7 标识。
- “把成长写进生长回路”。
- 学生身份与克制、诚实的内容语气。
- Java、JavaScript、MySQL、数据结构、前端和项目复盘主题。
- 音乐与运动作为真实生活线索。
- 现有文章、项目、评论、媒体和设置数据。
- 现有后台布局与认证方式。
- 语义 CSS 变量、深浅主题与焦点状态。
- Server Component 数据获取和 Client Component 叶子交互。
- 上传、Origin、限频和会话安全机制。

## 应演进

- 首页从长篇展示页改成响应式三栏生活空间。
- 绿色主强调改为琥珀主强调，绿色仅用于成功。
- 顶部导航扩展到完整个人空间。
- 个人资料、内容统计和站点统计改为真实数据库数据。
- 首页文章流改成多内容类型流。
- 增加持续播放但不自动播放的全站音乐状态。
- 增加城市级天气、配置时区时钟和有内容标记的日历。
- 增加低密度、可关闭、可降级的花瓣系统。
- 移动端增加固定底部 Dock，并给 Footer 预留安全空间。

## 应退役

- 首页占满可视区的大标题和超长连续 section。
- 把每一块内容都做成独立卡片。
- 仅作为装饰的技术网格和无数据标签。
- 任何占位社交链接、默认 GitHub 首页地址和示例邮箱公开展示。
- 视觉上重复的等宽卡片行。
- 与真实数据无关的统计数字。

## 设计拨盘

- `DESIGN_VARIANCE: 6`：三栏首页和混合内容流需要一定不对称，但长期阅读优先于实验构图。
- `MOTION_INTENSITY: 4`：花瓣、慢速 Marquee、轻量进入与按压反馈足够，不采用滚动叙事和高频循环。
- `VISUAL_DENSITY: 5`：首页承载状态、文章和生活组件，需要中等密度；正文和独立生活页保持更低密度。

## V2 设计系统选择

这是编辑型个人空间美学，不对应外部官方设计系统。继续使用现有 Tailwind CSS 4、原生 CSS 变量、`motion/react`、`lucide-react` 和 Next.js Server Components。不会安装 shadcn/ui、framer-motion、GSAP、Three.js 或额外状态库。

## 风险与控制

| 风险 | 控制 |
| --- | --- |
| 首页功能过多造成仪表盘感 | 中栏内容为主，左右组件限高，减少嵌套卡片 |
| 生活模块出现虚假内容 | 照片、音乐和友链默认真实空状态 |
| 新模型破坏双数据库一致性 | SQLite 与 MySQL 同步 schema、迁移和验证 |
| 播放器自动播放或 hydration 错误 | Provider 客户端隔离，初始静音状态不自动调用 `play()` |
| 天气失败阻断首页 | 服务端超时、缓存、异常回退和测试 mock |
| 花瓣影响性能和阅读 | 确定性 seed、有限节点、仅 transform/opacity、reduced-motion 完全关闭 |
| Dock 遮挡内容 | 主内容和 Footer 使用安全区底部间距 |
| 新表单带来垃圾提交 | Zod、Origin、IP 哈希、限频、最大长度和审核 |

## 审计结论

现有 V1 的数据、安全、SEO和内容基础是健康的，适合目标明确的增量演进。V2 不需要推倒重写；正确策略是扩充数据领域与后台能力，重组公共布局，并在原有语义变量和可访问性基线上建立温暖的个人生活层。
